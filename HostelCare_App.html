Mandatory Syllabi Rule Complied

1. Single Users Table RBAC

Dr. Sivakumar explicitly specified: "Maintain all users in a single Users table. Do NOT create separate tables such as Admin, Student, Faculty, Manager, Employee."

-- From database/01_schema_ddl.sql CREATE TABLE users ( user_id INT AUTO_INCREMENT PRIMARY KEY, reg_no VARCHAR(50) NOT NULL UNIQUE, full_name VARCHAR(100) NOT NULL, email VARCHAR(120) NOT NULL UNIQUE, password_hash VARCHAR(255) NOT NULL, role ENUM('STUDENT', 'WARDEN_ADMIN', 'TECHNICIAN') NOT NULL, phone_number VARCHAR(20), is_active BOOLEAN NOT NULL DEFAULT TRUE );
Password Security

2. BCrypt Salted Hashing

Plaintext passwords are never stored in the database. Every user password undergoes 10 rounds of cryptographic salting via BCrypt.

// Plaintext Password entered at login: "Password@123" // Stored Hashed String in MySQL: $2b$10$z8mY9wH7p6V3y0Dq1kQx.OqNn7qP1uQ2wE3r4t5y6u7i8o9p0a1s2 // Verification in authController.js: const isValid = await bcrypt.compare(password, user.passwordHash);
Stateless Auth

3. JWT Token Authentication

Upon successful login, the server issues a digitally signed JSON Web Token containing claims for role, registration number, and expiry.

// Active Signed JWT Token Header: { "alg": "HS256", "typ": "JWT" } // Active Decoded Token Claims: { "userId": 1, "regNo": "24BCI0006", "fullName": "Suhani Singh", "role": "STUDENT", "exp": 1792500000 }
Data Defense

4. SQL Injection Defense & Secrets

ORM-level parameterized queries prevent SQL injection attacks. Secrets are loaded via .env and excluded from version control via .gitignore.

# Environment Secrets (.env) - Excluded from Git: DATABASE_URL="mysql://root:****@localhost:3306/hostel_db" JWT_SECRET="pragya_24bci0280_suhani_24bci0006_jwt_secret_key" // Role-Based Authorization Middleware: Suhani24BCI0006_AuthMiddleware.suhani_authorizeRoles('WARDEN_ADMIN')
